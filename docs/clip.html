CLIP

그림과 말을 같은 공간에 놓다 — 라벨 대신 캡션으로 배우기

전통적 분류기는 학습 전에 정답 목록을 정해야 하고, 목록에 없는 것은 구조적으로 답할 수 없다. 더 근본적인 문제는 라벨이 의미를 담지 못한다는 것이다 — 클래스 37번은 그냥 37번이다. CLIP은 라벨 대신 인터넷에 이미 널려 있는 캡션을 감독 신호로 썼다. 그러자 고정 목록도, 별도 라벨링도 필요 없어졌다.

01고정된 목록이라는 제약

전통적인 이미지 분류기는 학습 전에 정답 목록을 미리 정한다. ImageNet이면 1000개 클래스다. 마지막 층의 출력 차원이 곧 그 개수이고, 목록에 없는 대상은 구조적으로 답할 수 없다.

새 범주를 추가하려면 그 범주의 라벨링된 이미지를 모아 다시 학습해야 한다. "이 사진에 냉장고가 있나?"를 묻고 싶으면 냉장고 데이터셋이 필요하다. 라벨링 비용이 능력의 상한을 정하는 구조다.

더 근본적인 문제는 라벨이 의미를 담지 못한다는 것이다. 모델에게 클래스 37번은 그냥 37번이다. "치와와"와 "웰시코기"가 둘 다 개라는 사실, "고양이"와 더 가깝고 "트럭"과는 멀다는 사실이 라벨 자체에는 없다. 정수 인덱스로 바꾸는 순간 그 정보가 버려진다.

CLIP의 출발점은 이것이다. 인터넷에는 이미 이미지와 그 설명이 함께 널려 있다. 캡션, alt 텍스트, 사진 제목. 이 자연어 설명을 라벨 대신 쓰면 고정 목록도, 별도 라벨링도 필요 없어진다.

02대조 학습 — 정답은 대각선에 있다

CLIP은 두 개의 인코더를 함께 학습시킨다. 이미지 인코더(ViT 또는 ResNet)와 텍스트 인코더(트랜스포머)가 각각 벡터를 내놓고, 두 벡터가 같은 공간에 놓이도록 훈련한다.

학습 방식이 요점이다. 배치에 N개의 (이미지, 텍스트) 쌍을 넣으면 가능한 조합은 N×N개다. 그중 대각선의 N개만 실제 쌍이고 나머지는 전부 잘못된 조합이다. 목표는 대각선의 유사도를 높이고 나머지를 낮추는 것 — 이것이 대조 학습(contrastive learning)이다.

대칭 대조 손실 — 이미지→텍스트, 텍스트→이미지 양방향
logits = (Ie · TeT) · exp(τ)  // τ = 학습되는 온도
L = ( CE(logits, labels) + CE(logitsT, labels) ) / 2
// labels = [0, 1, 2, …, N−1] — 즉 "정답은 대각선"
온도 τ가 학습된다는 점이 사소하지 않다. 대조 손실에서 온도는 분포의 날카로움을 정한다 — 너무 낮으면 어려운 음성 하나에 과하게 반응하고, 너무 높으면 양성과 음성의 구분이 흐려진다. CLIP은 이 값을 하이퍼파라미터로 두지 않고 로그 공간에서 함께 학습시켰다. 튜닝해야 할 손잡이 하나를 학습으로 넘긴 것이고, 이후 대조 학습 구현들이 대부분 이 방식을 따랐다.

03제로샷 — 분류기를 문장으로 만든다

학습이 끝나면 흥미로운 일이 가능해진다. 분류하고 싶은 범주를 문장으로 쓰기만 하면 그 자리에서 분류기가 만들어진다. 학습도, 라벨링도 없다.

  1. 후보 범주를 문장으로 쓴다 — "a photo of a dog", "a photo of a cat", …
  2. 각 문장을 텍스트 인코더에 넣어 벡터를 얻는다. (범주 수만큼 한 번씩)
  3. 분류할 이미지를 이미지 인코더에 넣어 벡터를 얻는다.
  4. 이미지 벡터와 가장 가까운 텍스트 벡터를 고른다.

2단계의 텍스트 벡터들이 사실상 분류기의 가중치 행렬 역할을 한다. 전통적 분류기라면 학습으로 얻어야 했을 것을, 문장을 인코딩해서 즉석에서 만드는 셈이다.

프롬프트가 성능을 바꾼다는 점도 이 구조의 직접적 귀결이다. 단순히 "dog"보다 "a photo of a dog"가 낫다 — 학습 데이터의 캡션이 대체로 문장 형태였기 때문이다. 도메인을 명시하면("a satellite photo of …") 더 오른다. 여러 템플릿의 텍스트 벡터를 평균 내는 프롬프트 앙상블도 표준 기법이 됐다.

04강점과 한계가 같은 곳에서 나온다

CLIP의 인상적인 성질은 분포 변화에 강하다는 것이다. ImageNet으로 지도학습한 모델은 스케치나 만화체 이미지에서 크게 무너지는데, CLIP은 상대적으로 잘 버틴다. 웹의 잡다한 이미지-텍스트 쌍으로 배웠으니 특정 데이터셋의 편향에 덜 물든 것이다.

그런데 같은 이유가 약점도 만든다.

  • 세밀한 구분에 약하다. 개와 고양이는 잘 나누지만 비슷한 새 품종을 가르는 일에는 전용 지도학습 모델이 낫다. 웹 캡션에 그런 세밀한 구분이 잘 등장하지 않기 때문이다.
  • 세는 것, 위치 관계에 약하다. "고양이 세 마리"나 "왼쪽에 있는 컵" 같은 표현은 대조 학습으로 얻기 어렵다. 캡션 전체와 이미지 전체를 하나의 벡터로 맞추는 방식이라 구성적 구조가 표현에 남지 않는다.
  • 데이터의 편향을 그대로 흡수한다. 웹에서 긁어온 4억 쌍에는 사회적 편향이 그대로 들어 있고, 모델이 그것을 학습한다. 원 논문도 이 위험을 명시했다.
  • 추상적·기술적 개념에 약하다. 학습 분포에서 먼 도표, 의료 영상, 위성 이미지 등은 제로샷 성능이 크게 떨어진다.
"제로샷"이라는 말의 범위에 주의해야 한다. 학습 데이터에 그 개념이 전혀 없었다는 뜻이 아니라, 해당 벤치마크의 라벨링된 학습셋을 쓰지 않았다는 뜻이다. 4억 쌍 안에 이미 그 범주의 이미지와 설명이 들어 있었을 가능성이 높다. 웹 규모 사전학습 모델의 평가에서 반복되는 주제이고, 벤치마크 오염 문제와도 맞닿아 있다.

05남긴 것 — 형식을 잇는 방법

CLIP의 실질적 영향은 제로샷 분류 성능보다 두 양식을 잇는 방법을 정립한 것에 있다. 이미지와 텍스트를 같은 공간에 놓는다는 발상은 이후 여러 곳에서 재사용됐다.

  • 텍스트-이미지 생성. Stable Diffusion은 텍스트 조건을 CLIP 텍스트 인코더로 처리한다. "무엇을 그릴지"를 이미지 공간과 맞물린 벡터로 바꾸는 일을 CLIP이 맡는 셈이다.
  • 시각 언어 모델. 오늘날 VLM은 대체로 이미지 인코더의 출력을 언어 모델의 입력 토큰으로 이어 붙인다. 두 인코더를 정렬하는 사전 단계에 CLIP 계열 학습이 쓰인다.
  • 검색과 필터링. 이미지 검색, 중복 제거, 데이터셋 정제에 광범위하게 쓰인다. LAION 같은 대규모 데이터셋 자체가 CLIP 점수로 걸러 만들어졌다.

한 걸음 물러나 보면 CLIP이 보여 준 것은 감독 신호를 어디서 얻을 것인가에 대한 답이다. 사람이 붙인 라벨 대신 이미 세상에 존재하는 짝지어진 데이터를 쓰면, 라벨링 비용이라는 상한이 사라진다. 자기지도 학습이 언어에서 한 일을 멀티모달에서 반복한 셈이고, 그 뒤로 "웹에 이미 있는 쌍을 찾아라"가 데이터 설계의 기본 전략이 됐다.
