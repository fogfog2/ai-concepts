Quantization

정밀도를 깎아 모델을 옮기다 — 무엇을 보존할 것인지 다시 정의하면서

양자화를 fp16을 int4로 바꾸는 반올림 작업이라고 하면 절반만 맞다. 그렇게 하면 4비트에서 모델이 무너진다. 실제로 작동하는 방법들은 모두 목표를 한 번 바꿔 놓고 시작한다 — 가중치를 정확히 보존하는 대신, 레이어의 출력을 보존한다. 이 재정의 하나로 70B 모델이 140GB에서 35GB로 내려가고, 소비자용 GPU에 들어가기 시작한다.

01가중치는 생각보다 좁은 곳에 모여 있다

70B 모델을 fp16으로 올리려면 70 × 2 = 140 GB가 필요하다. A100 80GB 두 장이다. 같은 모델을 4비트로 낮추면 약 35 GB — 소비자용 24GB 카드 두 장, 혹은 조금 더 줄이면 한 장에도 들어간다. 양자화가 하는 일은 이 산술이 전부다. 흥미로운 것은 왜 그래도 모델이 망가지지 않는가이다.

학습된 가중치의 분포를 그려 보면 대체로 0 근처에 뾰족하게 모인 종 모양이다. fp16은 6×10⁻⁸부터 65504까지를 표현하도록 설계됐지만, 실제 가중치는 그 범위의 아주 좁은 구간만 쓴다. 표현력의 대부분이 놀고 있다는 뜻이다. 양자화는 그 좁은 구간에 눈금을 촘촘히 다시 새기는 일이다.

비대칭 정수 양자화
s = (max(w) − min(w)) / (2b − 1),   z = round(−min(w) / s)
q = clamp(round(w / s) + z, 0, 2b − 1)
ŵ = s · (q − z)   // 복원 — w 와 정확히 같지는 않다

s는 눈금 간격(scale), z는 0이 정수 어디에 놓이는지(zero-point)다. 핵심은 s와 z를 어느 범위마다 따로 정하느냐다. 텐서 전체에 하나만 쓰면(per-tensor) 이상치 하나가 눈금 간격을 벌려 나머지를 뭉갠다. 그래서 실무에서는 보통 128개 값마다 한 쌍씩 둔다(group-wise). 이 경우 4비트 가중치에 스케일·제로포인트 오버헤드가 붙어 실효 비트는 4가 아니라 약 4.5가 된다.

02학습 후에 깎을 것인가, 깎으면서 학습할 것인가

갈림길은 하나다. 이미 학습된 모델을 건드리지 않고 바꿀 것인가(PTQ), 아니면 양자화된 상태를 가정하고 다시 학습할 것인가(QAT). 대형 언어모델에서는 거의 항상 PTQ다. 재학습 비용이 모델 크기에 비례해 감당이 안 되기 때문이다.

PTQ — 학습 후 양자화

보정용 데이터 수백 문장만 있으면 된다. GPU 한 장에서 수십 분. LLM 양자화는 사실상 전부 이쪽이다.

QAT — 양자화 인지 학습

학습 중 반올림을 흉내 내 모델이 미리 적응하게 한다. 품질은 낫지만 전체 재학습이 필요해 LLM에는 잘 쓰이지 않는다.

PTQ 안에서도 순진한 방법은 실패한다. 가중치를 그냥 가장 가까운 정수로 반올림하면(round-to-nearest) 4비트에서 모델이 무너진다. 각 가중치의 오차는 작아도, 한 레이어에 수백만 개가 쌓이면 출력이 원래와 달라지고 그 오차가 다음 레이어로 증폭되며 전파되기 때문이다.

여기서 관점이 하나 바뀐다. 목표는 가중치를 정확히 보존하는 것이 아니라, 레이어의 출력을 보존하는 것이다. 가중치가 좀 틀려도 출력이 같으면 상관없다. 이 재정의가 GPTQ와 AWQ 양쪽의 출발점이다.

최소화 대상 — 가중치 오차가 아니라 출력 오차 argminŴ ‖ W·X − Ŵ·X ‖²2   (X = 보정 데이터의 입력 활성값)

03GPTQ — 틀린 만큼 옆에서 보상한다

GPTQ는 가중치를 한 열씩 순서대로 양자화한다. 핵심은 하나를 양자화한 직후, 그로 인해 생긴 출력 오차를 아직 양자화하지 않은 나머지 가중치를 조금씩 움직여 상쇄하는 것이다. 먼저 처리한 것의 실수를 뒤에 남은 것들이 나눠서 갚는 구조다.

어느 방향으로 얼마나 움직일지는 2차 정보가 알려 준다. 출력 오차를 가중치에 대해 두 번 미분한 헤시안이 H = 2XXᵀ 형태로 나오는데, 이것은 보정 데이터만 있으면 구할 수 있다. OBQ 계열의 고전적 아이디어를 대형 모델에서 감당 가능하게 다듬은 것이 GPTQ의 기여다.

한 열을 양자화한 뒤 남은 열들에 뿌리는 보정
δ = − (wq − quant(wq)) / [H⁻¹]qq · H⁻¹q,:
// 오차를 헤시안이 가리키는 방향으로 나머지 열에 분배

원래 알고리즘은 오차가 큰 열부터 처리하려고 열마다 순서를 새로 정했는데, 이러면 행마다 순서가 달라져 느리다. GPTQ는 모든 행에 같은 순서를 쓴다는 단순화로 큰 속도를 얻었고, 여기에 콜레스키 분해로 수치 안정성을 확보하고 블록 단위로 갱신을 묶어 175B 모델을 GPU 한 장에서 약 4시간에 처리할 수 있게 만들었다.

04AWQ — 1%의 가중치가 결과를 좌우한다

AWQ는 다른 관찰에서 출발한다. 모든 가중치가 똑같이 중요하지 않다는 것이다. 실험해 보면 상위 약 1%의 가중치만 fp16으로 남겨도 성능 저하가 거의 사라진다. 그렇다면 그 1%를 찾아 지키면 된다.

결정적인 부분은 중요도를 무엇으로 재느냐다. 직관적으로는 크기가 큰 가중치일 것 같지만, AWQ의 측정은 다르다. 큰 활성값과 곱해지는 가중치가 중요하다. 가중치 자체가 작아도 입력이 크면 출력에 미치는 영향이 크기 때문이다. 그래서 가중치가 아니라 활성값 분포를 보고 중요한 채널을 고른다 — 이름의 A(activation-aware)가 여기서 온다.

다만 일부만 fp16으로 남기면 자료형이 섞여 커널이 느려진다. AWQ는 이를 피하는 우회로를 쓴다. 중요한 채널의 가중치에 s > 1을 곱해 키워 놓고 양자화한 뒤, 대응하는 입력을 1/s로 나눈다. 곱은 그대로인데, 키워서 양자화한 채널은 상대적 반올림 오차가 줄어든다.

스케일 이동 — 곱의 값은 보존하고 오차만 줄인다
Q(w · s) · (x / s) ≈ w · x   // 중요 채널일수록 s 를 크게

결과적으로 모든 가중치가 같은 4비트 형식으로 남아 커널이 단순하고 빠르다. 또 AWQ는 역전파나 헤시안을 쓰지 않아 보정 데이터에 덜 민감하고, 보정 집합과 다른 도메인에 일반화가 잘 되는 편이다.

방식기준필요한 것성격
RTN가장 가까운 눈금없음즉시, 4비트에서 붕괴
GPTQ출력 오차 (2차)보정 데이터 + 헤시안정밀, 다소 느림
AWQ활성값 크기보정 데이터 (통계만)빠름, 일반화 우수
SmoothQuant활성 이상치 이전보정 데이터W8A8 (활성값도 양자화)
QLoRA / NF4정규분포 최적 눈금없음학습용 (LoRA 결합)
가중치만 줄이면 절반만 푼 것이다. 위 방법 대부분은 가중치를 4비트로 두고 계산은 fp16으로 되돌려서 한다(W4A16). 이러면 메모리는 줄지만 연산량은 그대로다. 디코딩은 메모리 바운드라 그것만으로도 빨라지지만, 프리필처럼 연산 바운드인 구간에서는 이득이 적거나 역전될 수 있다. 활성값까지 8비트로 낮추는 W8A8(SmoothQuant 등)은 계산 자체를 정수 텐서 코어로 돌리려는 다른 갈래이고, 여기서는 활성값의 이상치가 주된 적이다.

05어디까지 내려갈 수 있는가

실무 감각으로는 8비트는 사실상 공짜이고, 4비트는 잘 된 방법이라면 대체로 안전하며, 3비트 이하부터는 눈에 띄게 나빠진다. 다만 이 경계는 모델 크기에 따라 움직인다. 큰 모델일수록 양자화에 강하다 — 파라미터가 많아 정보가 중복돼 있기 때문이다. 그래서 같은 메모리 예산이라면, 작은 모델을 fp16으로 쓰는 것보다 큰 모델을 4비트로 쓰는 편이 대체로 낫다는 경험칙이 성립한다.

벤치마크를 읽을 때 주의할 점이 하나 있다. perplexity는 양자화 손상에 둔감한 지표다. perplexity가 거의 그대로인데 코드 생성이나 다단계 추론에서 눈에 띄게 떨어지는 경우가 흔하다. 긴 출력에서 오차가 누적되는 작업일수록 손상이 드러난다. 실제로 쓸 작업으로 직접 재 보는 편이 안전하다.

  • 보정 데이터가 결과를 바꾼다. GPTQ는 보정 집합에 맞춰 오차를 최적화하므로, 보정에 쓴 텍스트와 실제 사용 도메인이 다르면 손해를 본다. 한국어로 쓸 모델을 영어 위키로만 보정하는 식의 실수가 흔하다.
  • 양자화와 파인튜닝을 함께. QLoRA는 베이스 모델을 4비트(NF4)로 얼려 두고 LoRA 어댑터만 학습한다. 메모리가 줄어 단일 GPU에서 65B 파인튜닝이 가능해졌다.
  • 형식은 런타임이 정한다. GGUF(llama.cpp), AWQ·GPTQ 체크포인트, bitsandbytes 등은 서로 호환되지 않는다. 쓸 엔진을 먼저 정하고 그에 맞는 형식을 받는 편이 낫다.

한 걸음 물러나 보면, 양자화가 작동하는 이유는 신경망이 애초에 과잉 정밀도로 학습되기 때문이다. fp32와 fp16이 필요한 것은 학습 중 그래디언트를 누적할 때이지, 학습이 끝난 뒤 추론할 때가 아니다. 학습과 추론이 요구하는 정밀도가 다르다는 이 비대칭이, 모델을 노트북에서 돌릴 수 있게 만든 근거다.
